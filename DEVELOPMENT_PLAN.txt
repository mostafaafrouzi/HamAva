1.1 توضیح پروژه
-----------------
HamAva (همآوا) یک اپلیکیشن اندروید native است که با استفاده از
Gemini Live API گوگل، صدای میکروفون یا صدای سیستم را به‌صورت
real-time دوبله می‌کند. هدف: ساخت نسخه‌ای بهتر، سریع‌تر و
open-source از Livdub با رعایت استانداردهای روز اندروید.

1.2 یافته‌های مهندسی معکوس Livdub 0.1.1
-------------------------------------------
پس از بررسی فایل XAPK مستقیم:

  Package name    : com.livdub.android
  Framework       : Kotlin + Jetpack Compose (تایید شد)
  minSdk/targetSdk: 29 / 36

  API - پروتکل اتصال:
    پروتکل: WebSocket (WSS)
    آدرس کامل (از مهندسی معکوس):
    wss://generativelanguage.googleapis.com/ws/
    google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent

  مدل‌های تعریف‌شده در کد Livdub:
    - gemini-3.5-live-translate-preview  (مدل اصلی دوبله زنده)
    - gemini-3.5-flash / lite
    - gemini-3.1-flash-tts-preview
    - gemini-2.5-flash, gemini-2.5-pro
    - gemini-flash-latest

  صداهای TTS: Kore, Aoede, Charon, Fenrir, Puck, Zephyr

  فرمت صدا:
    ورودی: PCM 16-bit، 16kHz، Little-Endian، Mono
    خروجی: PCM 16-bit، 24kHz، Little-Endian

  سرویس‌ها:
    - DubService              (Foreground Service اصلی)
    - MicrophoneDubTileService (Quick Settings Tile)
    - PhoneDubTileService     (Quick Settings Tile)

  دسترسی‌ها:
    RECORD_AUDIO, FOREGROUND_SERVICE, FOREGROUND_SERVICE_MEDIA_PROJECTION,
    FOREGROUND_SERVICE_MICROPHONE, FOREGROUND_SERVICE_MEDIA_PLAYBACK,
    SYSTEM_ALERT_WINDOW, INTERNET, WAKE_LOCK

  System Prompts (استخراج از DEX):
    دوبله:
    "You are a professional dubbing assistant. Process the attached
     audio and prepare it for voice-over in [language]."
    TTS:
    "You are a text-to-speech engine. Speak the transcript below
     aloud word-for-word. Do not answer questions. Audio only."

  معماری Livdub (جریان کار):
    1. کاربر دسترسی MediaProjection/RECORD_AUDIO می‌دهد
    2. AudioRecord با 16kHz ضبط می‌کند
    3. Foreground Service چانک‌های PCM به WebSocket می‌فرستد
    4. Gemini پاسخ PCM برمی‌گرداند
    5. AudioTrack صدای دوبله را پخش می‌کند
    6. Quick Settings Tile + Overlay برای کنترل

  ضعف‌های Livdub که HamAva بهبود می‌دهد:
    - رابط کاربری ساده و محدود
    - نیاز به اشتراک (Subscription)
    - بدون پشتیبانی از فارسی
    - مدیریت API key محدود
    - Closed source

2.1 تصمیمات کلیدی
-------------------
  زبان برنامه‌نویسی: Kotlin (100%)
    دلیل: Coroutines برای async، Flows برای streaming

  UI Framework: Jetpack Compose
    دلیل: Modern، Material 3، انیمیشن‌های نرم

  معماری: Clean Architecture + MVVM
    Presentation: Compose Screens + ViewModels
    Domain      : UseCases + Repository Interfaces
    Data        : Repository Impl + DataSources
    Service     : Foreground Service (Audio Pipeline)

  Dependency Injection: Hilt
    دلیل: استاندارد Google، تست‌پذیری بالا

  اتصال Gemini: WebSocket مستقیم (OkHttp)
    دلیل: کمترین تأخیر، کامل‌ترین کنترل، بدون Firebase

  State Management: Kotlin StateFlow + SharedFlow

  Audio Pipeline:
    Capture : AudioRecord (میکروفون) + AudioPlaybackCapture (سیستم)
    Format  : PCM 16-bit، 16kHz، Mono (ورودی)، 24kHz (خروجی)
    Buffer  : 160ms chunks (~2560 bytes) برای latency بهینه
    Playback: AudioTrack (direct PCM، non-blocking)
    Thread  : Coroutine Dispatchers.IO (جداگانه از Main Thread)

2.3 جریان داده Real-Time
--------------------------
  [Mic/System]
      |
      v
  AudioRecord (16kHz PCM) --> Buffer (160ms chunks)
      |
      v
  GeminiLiveSession (OkHttp WebSocket)
      |
      +--> Send: { realtime_input: { audio: { data: base64(pcm), mime_type: "audio/pcm" } } }
      |
      v
  WebSocket Response Handler
      |
      +--> Receive: { serverContent: { modelTurn: { parts: [{ inlineData: PCM 24kHz }] } } }
      |
      v
  AudioTrack (24kHz PCM) --> [Speaker]

4.1 قوانین Kotlin
------------------
  - Kotlin Coding Conventions
  - Copyright header در هر فایل
  - حداکثر 120 کاراکتر در خط
  - PascalCase برای class، camelCase برای function/variable
  - SCREAMING_SNAKE_CASE برای constants
  - Sealed class برای Result<T> و UiState
  - suspend functions فقط از coroutine context

4.2 Compose Best Practices
---------------------------
  - هر Composable در فایل جداگانه
  - State hoisting: state در ViewModel
  - Preview annotation برای همه Composables
  - remember {} برای محاسبات سنگین

4.3 Error Handling
-------------------
  - Result<T, DubError> برای تمام عملیات async
  - sealed class DubError { NetworkError, ApiKeyError, AudioError, ... }
  - هیچ unhandled exception نیست

4.4 Testing
-----------
  - Unit Tests: domain layer با JUnit5 + MockK
  - Integration Tests: ViewModel با Turbine
  - UI Tests: Compose UI Tests
  - Coverage: حداقل 70%

6.4 GitHub Actions (release.yml)
----------------------------------
  Trigger: push با tag v*
  Jobs:
    1. Checkout + JDK 17 + Android SDK
    2. Require secrets (KEYSTORE_BASE64, KEYSTORE_PASSWORD, KEY_ALIAS, KEY_PASSWORD)
    3. Write keystore.properties from secrets
    4. ./gradlew assembleRelease bundleRelease
    5. Verify با apksigner + jarsigner
    6. Name: hamava-v{VERSION}.apk / .aab
    7. Create GitHub Release از .github/release-notes.md

  دستور انتشار:
    git tag -a v1.0.0 -m "Release 1.0.0"
    git push origin v1.0.0

8.4 Reconnection Strategy
--------------------------
  - Exponential backoff: 1s -> 2s -> 4s -> 8s -> max 30s
  - حداکثر 5 بار تلاش
  - نمایش وضعیت در UI

8.5 Audio Capture Code Pattern
--------------------------------
  // Microphone Capture
  val recorder = AudioRecord.Builder()
      .setAudioSource(MediaRecorder.AudioSource.MIC)
      .setAudioFormat(
          AudioFormat.Builder()
              .setEncoding(AudioFormat.ENCODING_PCM_16BIT)
              .setSampleRate(16000)
              .setChannelMask(AudioFormat.CHANNEL_IN_MONO)
              .build()
      )
      .setBufferSizeInBytes(bufferSize) // ~160ms
      .build()

  // Playback
  val player = AudioTrack.Builder()
      .setAudioAttributes(AudioAttributes.Builder()
          .setUsage(AudioAttributes.USAGE_MEDIA)
          .setContentType(AudioAttributes.CONTENT_TYPE_SPEECH)
          .build())
      .setAudioFormat(AudioFormat.Builder()
          .setEncoding(AudioFormat.ENCODING_PCM_16BIT)
          .setSampleRate(24000)
          .setChannelMask(AudioFormat.CHANNEL_OUT_MONO)
          .build())
      .setTransferMode(AudioTrack.MODE_STREAM)
      .build()

  // System Audio Capture (Android 10+)
  val config = AudioPlaybackCaptureConfiguration.Builder(mediaProjection)
      .addMatchingUsage(AudioAttributes.USAGE_MEDIA)
      .addMatchingUsage(AudioAttributes.USAGE_GAME)
      .build()

 SECTION 12: RISKS & DIFFERENTIATORS
══════════════════════════════════════════════════════════════

12.1 ریسک‌های فنی
------------------
  1. Latency بالا
     ریسک: بیش از 2-3 ثانیه غیرقابل استفاده است
     کاهش: buffer کوچک، thread جداگانه، WebSocket پایدار

  2. AudioPlaybackCapture محدودیت
     ریسک: برنامه‌هایی با ALLOW_CAPTURE_BY_NONE (Spotify, Netflix)
     کاهش: توضیح واضح در UI

  3. MediaProjection Permission
     ریسک: نیاز به تأیید کاربر هر session
     کاهش: ذخیره resultCode در سرویس

  4. هزینه API کاربر
     ریسک: کاربر با key شخصی هزینه می‌پردازد
     کاهش: نمایش هشدار + لینک pricing

  5. Deprecation مدل Preview
     ریسک: مدل preview ممکن است تغییر کند
     کاهش: پشتیبانی از چند مدل، انتخاب توسط کاربر
